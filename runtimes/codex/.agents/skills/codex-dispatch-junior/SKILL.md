# Junior dispatch

Read the project's Codex Junior policy. Disabled or unconfigured means implement in
Builder; do not silently enable a helper. Require authorized delegation and red tests
already run by Builder. The brief names criteria, worktree/branch, red test paths and
command, red-test hashes and observed failure, initial dirty paths, allowed files,
forbidden/test files and dependency policy. Red tests need not be committed; record
the exact baseline without creating an unauthorized commit.

Use the Codex worker adapter and junior model row. Junior works in the Builder's
worktree; Builder pauses all writes and checkout-mutating commands there until
handback, including commits and test commands that regenerate files. Do not put another ticket
in this session. Junior cannot push, merge, review, codex-simplify or produce gate receipts.

Read back the actual diff, attribution and test results; rerun criteria from Builder.
A JUNIOR-DONE line alone does not prove completion. After two unsuccessful briefs or
a boundary crossing, stop Junior writing and return implementation to Builder, recording
why. Preserve partial work before any cleanup. Builder retains every later gate and
reports Junior contribution to Thomas. No shared-write overlap is permitted.
